# Event Console

**Event Console은 낯선대학 올출데이의 현장 운영을 위해 제작해 사용한 행사 콘솔 시스템입니다.**
한 대의 컴퓨터에서 조작 화면과 송출 화면을 분리해 점수, 타이머, 진행 순서, 영상·음악과 카메라 화면을 관리합니다.

낯선대학의 공식 제품이나 공식 배포물이 아니라, 제작자가 코드와 운영 경험을 개인적으로 정리해 공유하는 프로젝트입니다. 행사명은 제작 배경과 사용 사례를 설명하기 위해 언급합니다.

비개발 직군의 제작자가 퇴근 후 시간을 활용해 AI 도구들과 함께 작업한 프로젝트입니다. 기능이나 사용성에 미흡한 부분이 있을 수 있습니다.

제작자는 행사 콘솔 운영 경험 없이 개인적인 판단과 팀 내 시뮬레이션을 바탕으로 전체 흐름을 설계하고 개발했습니다. 모든 기능과 상황이 충분히 검증된 것은 아니므로, 자신의 행사와 장비에 맞춰 코드를 검토·수정하고 전체 진행을 리허설한 뒤 사용해 주세요.

이 저장소는 **본인의 AI CLI에 GitHub 링크를 전달하고, 자기 행사와 장비에 맞게 수정할 수 있도록** 코드와 제작·시뮬레이션 기록을 모아 둔 출발점입니다. 팀 구성, 진행 순서, 점수 규칙, 화면 디자인과 송출 환경을 AI와 함께 바꾸는 활용을 지향합니다. 아래 실행법은 현재 구현을 확인하는 방법이며, 실제 사용 전에는 각자의 환경에 맞춘 수정과 리허설이 필요합니다.

## 주요 기능

- 조작 화면과 프로젝터용 송출 화면 분리
- 점수 원장, 순위 계산, 타이머와 진행 큐 관리
- 카메라 화면, 영상 오버레이, 음악, 현장 사진 송출
- 조작 화면과 송출 화면의 실시간 상태 동기화
- 브라우저 로컬 저장, 자동 스냅샷, JSON 상태 백업·복구
- 오프라인 현장 운영을 고려한 로컬 폰트와 미디어 폴백

현재 큐와 점수 흐름은 원본의 4팀 행사 규칙을 기준으로 합니다. 팀 수, 종목 순서, 후반부 잠금, 시상 흐름처럼 행사 규칙에 묶인 부분은 범용 이벤트 빌더가 아닙니다. 다른 행사에 적용할 때는 `src/state.ts`, `src/cue.ts`, `src/scoring.ts`와 관련 테스트를 함께 수정해야 합니다.

출전 명단의 프리셋은 `샘플 1-1`처럼 표시한 가상 참가자입니다. 실제 참가자 명단은 조작 화면에서 입력하고 개인 운영 데이터로 보관하세요. 프리셋 UI나 명단 입력 방식을 개조할 때는 `src/control/tab-roster.ts`와 관련 테스트를 함께 확인합니다.

## 요구 사항

- Node.js 22.12 이상
- npm 10 이상
- 최신 Chrome 또는 Edge
- 카메라·마이크를 사용할 경우 브라우저 권한과 연결 가능한 입력 장치
- OBS로 방송·녹화·합성을 구성할 경우 **OBS Studio 설치 필수** — 설치되어 있지 않으면 [공식 다운로드](https://obsproject.com/download)에서 OS에 맞는 버전을 설치한 뒤 진행합니다.
- ProRes 원본을 브라우저용 알파 영상으로 변환할 경우 FFmpeg — [공식 다운로드 안내](https://ffmpeg.org/download.html)와 [제작·운영 팁](docs/OPERATION_TIPS.md)을 참고하세요.

브라우저 송출 창을 프로젝터에 직접 표시하는 구성은 OBS 없이 실행할 수 있습니다. OBS를 사용하는 구성에서는 앱 실행 성공과 별개로 캡처 소스·화면 기록 권한·오디오 경로를 확인해야 합니다. 현재 런처는 OBS나 FFmpeg를 자동 설치하지 않습니다.

macOS에서 주로 검증했습니다. 기본 웹 실행은 다른 운영체제에서도 가능하며, `launcher/launch.sh`의 브라우저 자동 열기는 macOS에서만 동작합니다. 다른 운영체제에서는 런처가 출력한 두 URL을 직접 여세요. 런처는 브라우저 정책이나 기존 브라우저 프로필을 변경하지 않습니다.

## 설치와 실행

저장소 루트에서 다음 명령을 실행합니다.

```bash
npm ci
npm run build
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다.

1. `조작 패널`을 운영자 화면에 엽니다.
2. 조작 패널의 `출력창 열기`를 눌러 송출 화면을 엽니다.
3. 송출 창을 프로젝터나 보조 디스플레이로 옮기고 전체화면으로 전환합니다.

두 창은 반드시 같은 브라우저의 같은 프로필에서 여세요. 상태 동기화는 같은 origin의 `BroadcastChannel`과 `localStorage`를 사용하므로 Chrome과 Edge를 섞거나 서로 다른 프로필을 쓰면 연결되지 않습니다.

OBS에서는 이 브라우저의 **송출 창을 창 캡처**하는 구성을 먼저 사용하세요. OBS 브라우저 소스에 같은 URL을 입력해도 Chrome의 저장소와 동기화 채널을 공유하지 않습니다. 브라우저 소스로 직접 연결하려면 별도 통신 구조를 구현해야 합니다. 구체적인 설정은 [OBS 운영 안내](docs/OPERATION_TIPS.md#obs로-송출녹화하기)에 있습니다.

개발 중에는 다음 명령을 사용할 수 있습니다.

```bash
npm run dev
npm test
npm run build
```

`npm run dev`는 소스 개발용입니다. 실제 운영 리허설은 배포 산출물을 제공하는 `npm start`로 진행하세요.

macOS에서는 런처로 빌드, 서버 시작과 두 창 열기를 한 번에 실행할 수 있습니다.

```bash
bash launcher/launch.sh
EVENT_CONSOLE_PORT=4189 bash launcher/launch.sh
```

기본 포트는 4173이며 `EVENT_CONSOLE_PORT`로 1024~65535 범위의 다른 포트를 지정할 수 있습니다. 선택한 포트가 이미 사용 중이면 런처는 기존 서버를 재사용하지 않고 중단합니다. 다른 앱이나 오래된 Event Console 복사본에 잘못 연결되는 것을 막기 위한 동작입니다.

## 제작을 돌아보며

우리 행사에 필요한 시스템을 정리해 보니, 큰 줄기는 스팅어, 라이브 중계, 음악 재생, 매치에 참여할 팀 선택과 해당 팀 정보의 자동 출력, 중간 점수 표시, 승리 영상 재생, 타이머, 그리고 라이브 화면에서 스토리 장면으로 넘어가는 연출 정도였습니다. 이렇게 실제 진행 순서에 맞춰 묶어 보니, 처음 생각했던 것만큼 많은 종류의 기능이 필요하지는 않았습니다.

준비한 영상과 실시간 화면을 필요한 순간에 연결하고, 운영자가 다음 순서를 무리 없이 진행할 수 있도록 만드는 데 집중했습니다. 각 기능을 구현하고 연결하는 데에는 세부적인 처리가 필요했지만, 행사에 필요한 범위를 먼저 정리한 덕분에 무엇을 만들고 어디까지 준비할지 판단하기가 한결 수월했습니다. 이 프로젝트에서 얻은 교훈도 우리 행사에 필요한 흐름을 구체적으로 정하는 일이었습니다.

현장에 있는 노트북의 상태나 운영체제를 사전에 파악하기 어려웠기 때문에, 제작자가 본인의 맥북을 직접 가져가 운영했습니다. 현장 컴퓨터에 맞춰 즉석에서 환경을 구성하기보다, 준비에 사용한 컴퓨터를 그대로 가져가 실행 환경의 변수를 줄이려는 선택이었습니다. macOS를 중심으로 준비하고 확인한 배경이기도 합니다.

다만, 빔프로젝터의 해상도가 FHD가 아닌 720으로 되어 있어서 당황했습니다. 텍스트를 더 작게 설정하지 않아서 다행이었습니다.

## 미디어 준비

이 프로젝트는 **영상 편집에 숙련된 제작자가 Envato 등의 템플릿·프리셋을 활용할 수 있는 작업 환경**에서 준비했습니다. 인트로·스팅어·대기 영상 등 다양한 연출 자료를 사전에 제작·렌더링해 두고, 현장에서는 준비한 영상을 재생하면서 점수·타이머·카메라 같은 실시간 출력 화면을 교체하는 방식으로 운영했습니다. 예시 영상의 연출에는 이러한 사전 영상 제작 작업과 콘솔의 실시간 제어가 함께 사용되었습니다.

미디어 기능은 **사전에 준비하고 점검한 환경에서, 예상 가능한 범위의 재생과 화면 전환을 다루는 것**을 목표로 했습니다. MadMapper나 OBS 수준의 폭넓은 미디어 처리·합성 기능을 구현하려는 목적은 없었습니다. 사용할 영상과 장비, 진행 순서를 미리 정할 수 있었기 때문에, 그 범위를 행사에 맞게 제어할 수 있으면 충분하다고 판단했습니다. 이 설계 전제는 다른 장비나 돌발 상황에서도 동작을 보장한다는 뜻은 아니며, 준비 범위가 달라지면 기능 수정과 리허설이 필요합니다.

행사에서 사용한 영상·음악·사진은 이 저장소에 포함하지 않습니다. 저장소를 처음 실행하면 외부 이미지를 복제하지 않고 이 프로젝트에서 직접 만든 SVG 안내 카드와 팀 마크가 기본 화면으로 표시되며, 행사 영상과 음악은 재생되지 않습니다.

자신이 사용할 권리가 있는 자료만 등록하세요.

**Chrome용 알파 스팅어는 등록 전에 변환이 필요합니다.** ProRes 4444(Alpha 포함) MOV는 제작용 원본으로 보관하고, **VP9 알파 WebM으로 변환한 파일을 등록하세요.** 원본 MOV를 넣었을 때 소리는 나지만 영상이 보이지 않는 사례가 있었습니다. 파일 등록·오디오 재생 성공은 영상과 알파의 재생 성공을 보장하지 않습니다. 일반 H.264 MP4 변환이나 확장자 변경·`-c copy` 재포장은 알파 보존용 변환을 대신하지 않습니다. [알파를 유지하는 FFmpeg 변환 명령](docs/OPERATION_TIPS.md#ffmpeg-변환-예시)을 참고하세요.

- 영상은 조작 패널의 `영상·에셋` 탭에서 등록합니다. 브라우저 IndexedDB에 저장되므로 등록한 브라우저 프로필에서만 사용할 수 있습니다.
- 사진은 `사진` 탭에서 등록합니다.
- 고정 배포 영상은 `public/media/`에 넣고 `public/media/manifest.json`에 등록할 수 있습니다.
- 시작 사진 묶음은 `public/photo-seed/`에 넣고 `public/photo-seed/manifest.json`과 파일명을 맞춥니다.
- 공개본의 음악 카탈로그는 비어 있으며, 조작 화면에는 음원 파일 업로드 기능이 없습니다. 음악을 사용하려면 `src/music.ts`의 `MUSIC_TRACKS`에 항목을 추가하고 그 `src` 경로에 파일을 배치한 뒤 다시 빌드해야 합니다. 해당 음악의 사용 권리는 별도로 확보하세요.

미디어가 없거나 로드에 실패하면 가능한 화면은 텍스트·도형 기반 폴백을 사용합니다. 영상 연출, 음악, 일부 행사 전용 장면은 자료가 없으면 생략되거나 단순 화면으로 표시되므로 실제 행사 전에 모든 큐를 끝까지 확인해야 합니다.

### 사진배경을 활용한 현장 운영

사진배경은 참가자들이 게임이 진행되는 동안 대기화면에서 방금 전 자신의 활약을 바로 볼 수 있도록 구현한 기능입니다. 실제 행사에서는 **현장에서 아이폰으로 촬영한 사진을 Apple 공유 앨범에 바로 올리고, 운영자가 전달받은 사진을 콘솔에 즉시 등록해 대기화면에 표시**하는 흐름으로 운영했습니다.

공유 앨범은 촬영자와 운영자 사이의 사진 전달 수단으로 사용했습니다. 콘솔에 넣는 단계는 운영자가 `현장 사진` 탭에서 진행하며, Apple 공유 앨범과 콘솔을 직접 자동 연동하는 기능은 포함되어 있지 않습니다. 자기 행사에 맞게 수정할 때는 사진을 전달받는 방식과 등록 담당자, 대기화면에 반영하는 흐름을 함께 준비하세요.

## 라이브 캡처·녹화 관련 유의사항

아이폰을 중계 카메라로 활용하는 구성도 가능합니다. 실제 행사에서는 카메라 연결용 micro HDMI 케이블을 두고 와서, **Mac의 연속성 카메라로 아이폰을 카메라 장치로 인식시켜 중계에 사용했습니다.** [아이폰 중계 카메라 연결과 현장 대체 경험](docs/OPERATION_TIPS.md#아이폰을-중계-카메라로-사용하기)에 준비 절차를 정리했습니다.

**현장중계 라이브를 캡처·녹화해 보관하는 통합 시스템은 포함되어 있지 않습니다.** 기존 카메라 화면 표시와 짧은 구간의 리플레이는 행사 전체의 중계 기록을 자동으로 저장하는 기능을 대신하지 않습니다.

행사 중계 영상을 남겨야 한다면 OBS 등에서 캡처·녹화 구성을 별도로 준비하세요. 콘솔 실행만으로 녹화가 시작되지는 않습니다. 행사 전에 영상과 소리가 모두 들어오는지, 저장 위치·용량이 충분한지, 녹화 파일을 실제로 재생할 수 있는지 확인해야 합니다. [OBS 준비 절차](docs/OPERATION_TIPS.md#obs로-송출녹화하기)를 참고하세요.

## 브라우저 데이터와 백업

상태는 `localStorage`에, 등록 영상·사진과 자동 스냅샷은 IndexedDB에 저장됩니다. 브라우저 데이터 삭제, 시크릿 창 종료, 다른 프로필 사용은 저장된 운영 자료를 없애거나 보이지 않게 만들 수 있습니다.

행사 전에는 다음을 준비하세요.

1. `설정` → `JSON 내보내기`로 점수·팀·설정 상태를 백업합니다.
2. 등록한 영상·사진 원본을 별도 폴더에도 보관합니다. JSON 백업에는 영상 파일이 포함되지 않습니다.
3. 백업 브라우저나 백업 컴퓨터에서 미디어를 다시 등록하고 JSON을 가져오는 절차를 확인합니다.
4. 브라우저 자동 업데이트나 데이터 정리는 행사가 끝난 뒤로 미룹니다.

## 현장 리허설 체크리스트

- 조작 화면과 송출 화면을 같은 브라우저 프로필에서 열었는가
- 프로젝터 해상도와 전체화면 전환을 확인했는가
- 카메라 권한, 실제 입력 장치, 화면 비율을 확인했는가
- 송출 장치에서 영상과 음악의 소리가 실제로 들리는가
- 브라우저 자동재생이 막힐 때 송출 창을 클릭해 해제할 수 있는가
- 모든 큐, 점수 확정·되돌리기, 타이머, 암전, 영상 종료 후 장면을 확인했는가
- JSON 상태 백업과 미디어 원본의 복구 경로가 준비됐는가
- 중계 기록이 필요하다면 별도 캡처·녹화를 시작했고 실제 저장 파일을 확인했는가

카메라와 오디오는 브라우저·운영체제·캡처 장치 조합에 따라 동작이 달라집니다. 자동 테스트 통과는 현장 장비 리허설을 대신하지 않습니다.

## 구조

배포판은 최종 파일 상태를 하나의 커밋으로 정리했습니다. 각 파일과 폴더의 역할은 [파일·폴더 안내](docs/FILE_GUIDE.md), 설계 이유는 [개발 기록](docs/DEVLOG.md)에 남겼습니다.

| 폴더 | 역할 |
| --- | --- |
| `src/` | 상태·점수·동기화·미디어 제어와 기능별 테스트 |
| `src/control/` | 운영자가 사용하는 조작 화면 |
| `src/scenes/` | 관객에게 표시하는 송출 장면 |
| `src/styles/`, `src/fonts/` | 화면 스타일과 포함 폰트 |
| `public/` | 기본 SVG·아이콘과 미디어·시작 사진 목록 |
| `docs/` | AI 수정 가이드, 구조·운영·개발 기록과 파일 안내 |
| `launcher/`, `tests/` | 로컬 실행기와 실행기 테스트 |
| `licenses/` | 폰트 저작권·라이선스 원문 |
| `.github/workflows/` | 자동 검증 설정 |

- `control.html`, `src/control.ts` — 조작 화면 진입점
- `display.html`, `src/display.ts` — 송출 화면 진입점
- `src/state.ts`, `src/types.ts` — 상태 모델과 리듀서
- `src/cue.ts`, `src/scoring.ts` — 행사 진행 큐와 점수 규칙
- `src/sync.ts` — 두 창의 상태 동기화
- `src/db.ts` — IndexedDB 미디어·사진·스냅샷 저장
- `src/scenes/` — 송출 장면 렌더링
- `src/control/` — 조작 탭과 입력 UI

자세한 설명은 `docs/ARCHITECTURE.md`를 참고하세요.
