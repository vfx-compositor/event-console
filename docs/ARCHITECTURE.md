# 아키텍처

## 실행 구조

Event Console은 TypeScript와 Vite로 만든 다중 페이지 웹앱입니다. 백엔드나 원격 데이터베이스 없이 한 컴퓨터의 브라우저 안에서 동작합니다.

```text
index.html
├── control.html → src/control.ts → 운영 입력과 상태 변경
└── display.html → src/display.ts → 상태를 구독해 송출 장면 렌더링
```

조작 화면은 상태를 변경하는 단일 리더입니다. 송출 화면은 상태를 구독하고 영상 종료, 카메라 상태, 오디오 잠금 같은 런타임 이벤트만 조작 화면에 돌려보냅니다.

## 상태와 점수

`src/types.ts`가 전체 상태 형식을 정의하고 `src/state.ts`가 초기 상태, 직렬화, 정규화와 reducer를 소유합니다. UI는 action을 보내고 reducer가 새 상태를 만드는 단방향 구조입니다.

점수의 정본은 append-only 원장입니다. 확정과 취소는 원장 항목으로 남고, 화면의 점수와 순위는 원장에서 계산합니다. `src/scoring.ts`는 순위별 배점과 공동 순위 계산을 담당합니다.

## 창 동기화

`src/sync.ts`는 같은 origin의 `BroadcastChannel`을 기본 경로로 사용하고 `localStorage`의 `storage` 이벤트를 폴백으로 사용합니다. 늦게 열린 송출 화면은 조작 화면에 현재 상태를 요청합니다.

브라우저 프로필이 다르면 두 저장소와 채널이 분리됩니다. 조작 화면과 송출 화면을 같은 브라우저 프로필에서 열어야 하는 이유입니다.

## 저장소

- `localStorage` — 직렬화된 현재 운영 상태와 일부 UI 설정
- IndexedDB `assets` — 사용자가 등록한 영상과 이미지 blob
- IndexedDB `photos`, `photoThumbs` — 현장 사진과 썸네일
- IndexedDB `snapshots` — 주기적인 상태 복구 지점
- IndexedDB `kv` — 큰 상태에서 분리한 최신 보조 값

`설정`의 JSON 내보내기는 상태를 백업하지만 영상 blob 자체는 포함하지 않습니다. 미디어 원본은 별도로 보관해야 합니다.

## 진행과 장면

`src/cue.ts`는 기본 제공 행사 템플릿의 진행 순서와 큐 실행 action을 구성합니다. `src/scenes/`의 함수는 현재 상태를 가상 DOM으로 바꾸고, `src/display.ts`가 송출 화면에 반영합니다. 영상·음악·카메라의 재생 제어는 상태 전환과 분리된 전용 모듈이 담당합니다.

현재 도메인 모델에는 4팀, 1부 종목, 잠금된 후반부 단계, 시상 순서 같은 원본 행사의 규칙이 들어 있습니다. 이를 범용화하려면 상태 스키마만 바꾸는 것으로 충분하지 않으며 큐, 점수, 조작 탭, 송출 장면과 회귀 테스트를 함께 갱신해야 합니다.

## 미디어 경계

저장소에는 행사 원본 미디어를 포함하지 않습니다. 사용자는 브라우저 UI로 자료를 등록하거나 `public/media/manifest.json` 계약에 맞춰 자신이 배포할 수 있는 파일을 둘 수 있습니다. 누락된 자료는 가능한 장면에서 텍스트·도형 폴백으로 처리합니다.

폰트는 오프라인 실행을 위해 `src/fonts/`에 포함하며, 각 폰트는 SIL Open Font License 1.1을 따릅니다. 자세한 고지는 `THIRD_PARTY_NOTICES.md`에 있습니다.

## 신뢰 경계

Vite preview 서버는 정적 파일을 제공합니다. 애플리케이션 인증이나 원격 권한 계층은 없습니다. 운영 서버는 loopback에서만 사용하고 신뢰하지 않는 네트워크에 공개하지 않는 것이 배포 전제입니다.

카메라 영상은 브라우저의 `getUserMedia`로 받아 송출 화면에서 사용합니다. 슬로우 리플레이는 브라우저 `MediaRecorder` 지원에 의존합니다. 장치 권한, 코덱, GPU 합성, 자동재생 정책은 자동 테스트만으로 보장할 수 없어 현장 장비 리허설이 필요합니다.
